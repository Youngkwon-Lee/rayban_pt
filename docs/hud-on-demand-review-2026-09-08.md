# HUD 요청형 검토 개선

2026-09-08. Web App HUD와 후보 결정 API만 변경했다. 네이티브 iOS HUD,
직접 `/neural-band/event`를 호출하는 별도 입력 경로는 이번 변경 대상이 아니다.
후속 작업에서 외부 제스처 경로를 보완했다. 현재 핀치·명시적 결정 계약과 검증은
`hud-input-progress.md` 및 `neural-band-integration.md`를 따른다.
`design/dry_run` 유지. 배포·임상 데이터 전송·생산 DB 쓰기는 하지 않았다.

## 목적과 화면 규칙

치료사의 주 과제는 세션을 기록하면서 필요한 시점에만 후보·안내를 확인하는 것이다.
녹화 중 주 동작은 영상 중지, 직접 연 후보에서는 승인, 종료 후에는 HUD 마치기다.
헤더·환자 별칭·현재 내용·동작 영역의 네 묶음을 유지한다. 기존 색상·서체·600×600
크기·88px 버튼을 사용하고, 자동으로 펼쳐지던 별도 안내 영역을 제거했다.

- 시작 전: 기존 방문/기록 미리보기로 준비한다. 새 계획 편집 기능은 추가하지 않았다.
- 진행 중: 후보가 도착해도 영상 중지 버튼과 기록 상태를 유지한다.
- 요청형 검토: 후보 보기를 눌러 열고 위/좌우 키로 세부 내용을 확인한다.
  나중에 또는 Escape는 후보를 승인·폐기하지 않고 세션으로 돌아간다.
- 안내: 새 안내는 안내 보기를 눌렀을 때만 현재 내용 영역에서 표시한다.
  확인한 안내는 같은 ID로 다시 알리지 않으며, 다음 안내가 오면 다시 표시할 수 있다.
- 종료 후: 미검토 초안과 휴대폰 검토 안내를 표시한다. HUD 마치기는 화면만 닫으며
  세션 초기화·후보 승인·서명 요청을 보내지 않는다. 미승인 후보가 있으면 열어볼 수 있다.
- 긴 차트·편집·서명은 휴대폰에 남긴다. 실제 휴대폰 앱을 여는 새 딥링크는 추가하지 않았다.

빈 상태에서는 방문 후보가 없으면 시작을 비활성화한다. 업로드·분석 중에는 추가
녹화/종료 동작을 숨긴다. 오류에서는 상태 확인과 HUD 닫기만 제공하고, 오프라인에서는
쓰기 동작을 막는다. 안내·후보 상세는 연결 오류 시 닫으며 자동 재연결 후 상태를 갱신한다.
이전 세션의 기록 미리보기를 다른 세션에 재사용하지 않도록 세션 ID를 연결했다.

## 승인 대상 고정

Web App의 승인/폐기 요청은 `/glass/command`에 `candidate_id`를 함께 보낸다.
서버는 해당 값이 현재 후보와 다르면 `HUD_CANDIDATE_CHANGED`를 반환하고
결정을 적용하지 않는다. 사용자에게 후보를 다시 열도록 안내한다.
기존 클라이언트의 ID 없는 요청은 호환성을 위해 기존 동작을 유지한다.

전면적인 동시성 제어나 모든 입력 경로의 승인 정책을 변경한 것은 아니다.
후보 내용 변경의 버전 비교, 다중 치료사 동시 검토, 실제 Neural Band는 후속 검증 대상이다.

## 검증

실행한 명령:

```bash
# 프로젝트 루트
node --check server/static/glass-webapp/app.js
git diff --check
python3 scripts/preview_hud.py --port 8793

# server 디렉터리
./.venv/bin/python mrbd_hud_smoke_test.py
./.venv/bin/python smoke_test.py
./.venv/bin/python visit_session_smoke_test.py
```

세 스모크 테스트와 JS 문법·diff 검사는 통과했다. 기존 정적 레이아웃 검사는
빈 안내 행을 없앤 네 행 레이아웃으로 갱신하고, 자동 다섯 번째 안내 영역이 없음을
검사한다. 서버 스모크에 오래된 후보 ID의 승인과 폐기를 모두 거부하고 현재 후보를
보존하는 회귀 검사를 추가했다. 올바른 ID의 폐기 성공도 확인한다.

Codex in-app browser, 합성 fixture, 600×600에서 확인한 흐름:

1. 시작 전 자료 확인 → 방문 시작 → 기록 보기 → Escape로 복귀.
2. 녹화 중 후보 도착 → 주 동작이 영상 중지로 유지됨.
3. 후보 열기 → 위/오른쪽 키로 다음 세부 항목 확인 → 나중에로 복귀.
4. 후보 열기·항목 탐색·보류 과정의 HTTP 쓰기 요청이 0건임.
5. 명시적 승인 시 표시했던 후보 ID를 포함한 요청 정확히 1건 → 녹화 화면 복귀.
6. 안내 자동 팝업 없음 → 안내 보기 → Escape로 복귀.
7. 업로드 중 추가 녹화·종료 동작 없음.
8. 오프라인에서는 HUD 닫기만 제공.
9. 오류에서는 상태 확인·HUD 닫기만 제공.
10. 종료 후 검토 안내와 HUD 마치기 표시, 녹화 재시작·승인 동작 없음.

최종 프리뷰 자바스크립트에서 브라우저 오류·경고가 확인되지 않았다.
중간 검증에서 구버전 자바스크립트 캐시 오류가 있었으며 프리뷰 서버에
`Cache-Control: no-store`를 추가하고 최신 자산으로 다시 검증했다.

임시 화면·검증 기록: `/tmp/rayban-hud-ux-20260908/`.
브리지 테스트 로그: `/tmp/rayban-hud-contract.log`, `/tmp/rayban-hud-bridge.log`,
`/tmp/rayban-hud-visit.log`.

실제 안경 렌즈·Neural Band 입력·녹화·마이크·실제 업로드와 200% 글자 확대/스크린리더
검증은 수행하지 않았다. 이 프리뷰는 메모리 내 합성 데이터만 사용하며 로컬 브리지,
안경 또는 원격 서버에 연결하지 않는다. 서버를 재시작하면 fixture 상태는 초기화된다.

작업 중 디스크 부족으로 파일 쓰기와 첫 브리지 테스트가 실패했다. 이전 작업에서
생성한 `.deriveddata-device/SourcePackages`의 SDK 체크아웃·다운로드 캐시만 삭제한 뒤
원본 변경 상태를 다시 확인하고 재검증했다. 해당 캐시는 SwiftPM에서 재다운로드할 수 있다.
